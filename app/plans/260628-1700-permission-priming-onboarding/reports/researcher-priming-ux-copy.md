## Executive Summary

Permission priming increases opt-in rates by 28–60% when executed correctly. Two key patterns: (1) **contextual timing** — ask when the user actually needs the feature, (2) **value-first messaging** — explain the benefit before the OS permission dialog appears. For ancu365, target 60%+ push notification opt-in (vs. global 43.9% on iOS) and 75%+ camera permission grant rate using Vietnamese-first copywriting, soft re-ask patterns at 3–5 day mark, and illustrated priming screens.

## 4. Anti-Patterns to Avoid

### CRITICAL — Block These in Review

| Anti-Pattern | Why It Fails | Impact |
|--------------|------------|--------|
| "Bật thông báo để có trải nghiệm tốt nhất" (Generic) | 0% value justification | **8% opt-in rate** |
| Ask at app launch (no context) | User hasn't experienced value yet | 13.85% opt-in (ATT baseline) |
| "Don't Allow" hidden or styled like text | Dark pattern; regulatory risk (CPPA 2024) | Legal liability + user backlash |
| Multiple permissions in one sheet | Cognitive overload; users deny all | 20–30% grant rate vs. 70%+ single-permission |
| Urgent language ("Act now!") without urgency | Feels manipulative to Vietnamese users | 15–20% opt-in, trust damage |
| Ask for camera + location + contacts together | Feature-gating (contacts for photos?) | Perceived privacy invasion; 5% opt-in |

### SOFT PATTERNS — Can Work But Risky

- **Re-asking after 1 day:** Too aggressive; 40% deny again
- **Blocking core feature without permission:** (e.g., booking blocked unless location enabled) Causes uninstalls
- **No "Don't Allow" button or hiding it:** CPPA violation since 2024; regulatory enforcement active

## 5. Re-Prompt Strategy & Timing

### First Denial Flow
1. **User denies permission** (e.g., camera for CCCD upload)
2. **Show inline help:** "Chúng tôi cần ảnh chứng minh thư để xác minh. Bạn có thể cấp quyền trong Cài đặt ứng dụng → Quyền."
3. **Soft surface** (not modal): Settings card or inline banner
4. **Do NOT block feature** — allow manual entry alternative (e.g., type ID number)

### Re-Ask Timing (Evidence-Based)
- **3–5 day mark:** Best re-ask window. Users with ~15+ app sessions and successful booking experience → **80% acceptance** (vs. immediate re-ask: 30%)
- **DO NOT re-ask** if user denies twice in same session
- **Trigger re-ask** when user tries feature again (e.g., host tries to upload photo on day 4)

### Soft Re-Ask Patterns

#### Pattern A: Settings Card (Recommended for ancu365)
```
┌─────────────────────────────┐
│ 📸 Tối ưu hóa ảnh            │
│                               │
│ Cho phép camera để chụp ảnh  │
│ phòng nhanh chóng.            │
│                               │
│  [Bật → Đi tới Cài đặt]   │
└─────────────────────────────┘
```

#### Pattern B: Inline Banner (Less Intrusive)
```
ℹ️ Bạn đã tắt camera. Bật trong Cài đặt để chụp ảnh phòng.
[Mở Cài đặt] [Bỏ qua]
```

#### Pattern C: Periodic In-App Prompt (After 5+ sessions)
Show once every 7 days max; dismiss with "Để sau" option.

## 7. Iconography & Illustration Strategy

### Recommendation: **Illustrated Priming** (not icon-only)

| Approach | Trade-Off | Best For |
|----------|-----------|----------|
| **Icon Only** (48px) | Low emotional impact; cold | Speed; secondary features |
| **Illustration** (200×200px) | Warm, trustworthy; slows load; must animate well | Primary CTAs (CCCD, house photo) |
| **Animation** (Lottie) | Highest engagement; adds delight; risk: can feel gimmicky | Post-booking flows, non-critical features |

### Recommended: Storyset (Real Estate + People Illustrations)

**Why Storyset over unDraw:**
- Real estate illustrations available (Rafiki style)
- Character skin tone / outfit customization (inclusive)
- Built-in animation export to GIF/Lottie JSON
- Can customize colors to match ancu365 brand (#B71C1C red, #00A65A green)

**Illustration Themes:**
- **CCCD Upload:** "Người đang chụp ảnh tài liệu" (Person photographing document)
- **House Photo Upload:** "Người chụp ảnh căn phòng" (Person photographing room) or "Chủ nhà tạo danh sách" (Host creating listing)
- **Profile Avatar:** "Người chỉnh sửa hồ sơ" (Person editing profile)
- **Push Notification:** "Người nhận thông báo di động" (Person receiving mobile notification)

**Export Settings:**
- Animated GIF (2–3 sec loop) OR
- Lottie JSON (lighter, better mobile performance, loopable)
- PNG static fallback for older devices

## 8. Accessibility Checklist

### Contrast Ratios (WCAG AA Compliance)
- **Headline text:** Minimum **4.5:1** (small text) or **7:1** (mobile best practice)
- **Body copy:** Minimum **4.5:1** against background
- **Buttons:** Text **4.5:1**, button outline **3:1** against background
- **Tool:** Use WebAIM Contrast Checker to verify all combinations

### Button Design (Equal Visual Weight)
```
❌ WRONG:
┌──────────────────┐ ← "Bật Ngay" (filled, prominent)
│ Bật Ngay         │
└──────────────────┘
  Để Sau ← ("Để Sau" as text link, easy to miss)

✅ CORRECT:
┌──────────────────┐
│ Bật Ngay         │ ← Primary (filled, red #B71C1C)
└──────────────────┘
┌──────────────────┐
│ Để Sau           │ ← Secondary (outline, same size/weight)
└──────────────────┘
```

### Screen Reader Labels
```typescript
// For close button
<button
  aria-label="Đóng yêu cầu cấp quyền camera"
  onClick={handleClose}
>
  ✕
</button>

// For primary CTA
<button
  aria-label="Bật camera để xác minh chứng minh thư"
  onClick={handleAllow}
>
  Bật Ngay
</button>

// For secondary CTA
<button
  aria-label="Hủy yêu cầu cấp quyền, có thể yêu cầu lại sau"
  onClick={handleDefer}
>
  Để Sau
</button>

// For illustration
<img
  src="camera-illustration.svg"
  alt="Minh họa: người đang chụp ảnh chứng minh thư bằng camera điện thoại"
  role="presentation"
/>
```

### Touch Target Minimum Size
- **Primary button:** 48px height × 100% width (full-width for mobile)
- **Secondary button:** 48px height × 100% width
- **Minimum safe padding:** 8px on all sides between interactive elements

### Focus Management
- **When sheet opens:** Focus moves to headline (role="dialog" with `aria-labelledby`)
- **When sheet closes:** Focus returns to triggering button
- **Keyboard navigation:** Tab through headline → body text → Primary button → Secondary button → Close button

## 9. Implementation Checklist

### Pre-Launch
- [ ] Copy review by native Vietnamese speaker (tone, formality, cultural fit)
- [ ] Contrast ratio test on real device (not screenshot) — minimum 7:1 on mobile
- [ ] Accessibility audit: VoiceOver (iOS) + TalkBack (Android) testing
- [ ] A/B test copy variants on 5% of users (short vs. medium)
- [ ] Illustration customization: Verify brand color (#B71C1C, #00A65A) applies correctly
- [ ] Button tap target test: 48px minimum, spacing tested on 5.4"–6.5" devices

### Post-Launch Monitoring
- [ ] Week 1: Measure opt-in rate by variant (short/medium/long copy)
- [ ] Week 2–4: Track re-ask acceptance rate after 3–5 day window
- [ ] Monthly: Monitor if users deny permission twice; analyze why
- [ ] Quarterly: A/B test illustration vs. icon-only priming
